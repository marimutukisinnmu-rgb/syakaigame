# 超大規模HTML経済社会ゲーム

商品販売、店舗・企業運営、製造、供給網、価格形成、企業グループ、買収、競争政策、倒産などを題材にした経済社会シミュレーションのプロトタイプです。

## Demo 0.2

**[ブラウザーでDemoを開く（GitHub Pages）](https://marimutukisinnmu-rgb.github.io/syakaigame/)**  
[HTMLソースを見る](https://github.com/marimutukisinnmu-rgb/syakaigame/blob/main/index.html)

単一のHTMLファイルで動き、外部ライブラリやアプリのインストールは不要です。PC・スマートフォンのブラウザーで操作できます。進行状況はそのブラウザーの `localStorage` に保存され、他端末とは同期しません。

### 遊べる機能

- **市場・仕入れ：** 木材、鉄材、小麦粉、電子部品を仕入れる。価格は日ごとに変動。
- **製造：** 木製チェア、パン、ワークデスク、スマートランプを製造する。
- **価格・販売：** 商品価格を調整し、1日進めて需要に応じた販売を精算する。
- **経営：** 広告で評判と需要を伸ばし、架空のNPC従業員を雇って生産能力を上げる。
- **会社・資金：** ゲーム内で法人化し、デモ銀行から借入・返済する。
- **企業再編：** 法人化した会社がNPC事業を買収できる。買収は対象製品の需要を上げる一方、日次管理費がかかる。
- **倒産・再起：** 資金繰りが一定条件を満たして破綻した場合、在庫等をゲーム内評価し、会社を清算して再起資金からやり直す。これはゲーム独自の簡略ルール。
- **帳簿：** 日次売上・原価・運営費・利益、取引履歴、市場ニュースを確認できる。
- **自動保存：** 進行状況は使用中のブラウザーに保存される。リセットは画面内の「最初から」から実行できる。

### はじめかた

1. Demoを開き、最初の在庫を確認する。
2. 「市場・仕入れ」で素材を補充し、「工場・生産」で商品を作る。
3. 商品価格を調整し、ダッシュボードの「1日進める」で販売を精算する。
4. 現金が増えたら法人化やNPC事業の買収に挑戦する。買収には取得費用だけでなく、毎日の管理費も必要。
5. 借入の期限と現金残高を確認する。資金不足が続いたら「企業再編・倒産」でゲーム内の再起条件を確認する。

### Demoの範囲と制限

- マルチプレイ、サーバー保存、プレイヤー間取引・交渉は未実装です。
- 買収対象は固定の架空NPC事業です。プレイヤー会社どうしの合併や敵対的買収は未実装です。
- カルテル等の競争法違反を自動判定する機能はありません。価格が一致するだけで違反と判定しない方針を設計メモに記載しています。
- 法令データを読み込んで現実の法律を自動適用する機能はありません。会社設立、融資、倒産、債務リセットはゲーム独自の簡易ルールです。
- 通貨は架空の「ミライ円」です。ゲーム内通貨・資産を現実のお金、商品、金券、ギフトカード等と交換することは禁止です。
- ゲーム内の雇用は架空のNPCのみ。実在のプレイヤーへ現実世界の仕事を依頼したり、現実の報酬を支払ったりする仕組みはありません。
- セーブデータはブラウザー内だけに保存されます。ブラウザーのデータ消去、プライベートモード、別端末への移行では失われる場合があります。

## 法令データの調査資料

法令データの構造検査、収録数、CSV/XML突合、検査方法と限界、ゲーム設計に関係する法令分野は、専用の `docs` ブランチに記録しています。

- [日本法令データ一式の機械的検査・経済社会ゲーム向け制度設計メモ](https://github.com/marimutukisinnmu-rgb/syakaigame/blob/docs/japan-law-data-review.md)
- [法令データ検査スクリプト](https://github.com/marimutukisinnmu-rgb/syakaigame/blob/docs/scripts/verify_law_archive.py)

法令XMLを保管・検索することと、現実の法律を自動で正確に適用することは別です。法令の施行時点、附則、経過措置、委任命令、個別の利用条件を確認し、法的判断を保証する製品であるかのように表示しないでください。

## 運営・安全方針

学校内コミュニティでの利用も想定し、実名・学籍情報・住所・電話番号などの不要な個人情報を集めないことを基本とします。実際に運用する前に、学校・保護者等の了承が必要かを確認してください。チャットを追加する場合は通報窓口、ミュート・ブロック、対応手順、ログの閲覧権限と保存期間を設計してください。
